0Entender e preparar

Antes de digitar, entenda o que vamos construir e deixe a pasta pronta.

1O que é um PWA?

PWA (Progressive Web App) é um site que pode ser instalado como aplicativo. Ele ganha ícone na tela inicial, abre em tela cheia (sem a barra do navegador) e pode funcionar sem internet. Não precisa da Play Store nem da App Store: o próprio navegador faz a instalação.

Para um site virar PWA, ele precisa de 3 coisas:
• HTTPS (endereço seguro) → o GitHub Pages já dá isso de graça;
• um manifest.json → a "carteira de identidade" do app (nome, cores, ícones);
• um service worker (sw.js) → um ajudante que guarda os arquivos no celular para o app abrir offline.

✔ Confira: Você consegue explicar para um colega as 3 coisas que um PWA precisa.

2Criar a pasta e os arquivos

Na Área de Trabalho, crie a pasta campus-app (minúsculo, sem espaço). Abra a pasta no VS Code (File → Open Folder). Por enquanto, crie só dois arquivos vazios: index.html e style.css. Os outros arquivos (app.js, manifest.json, sw.js e os ícones) vamos criar na hora certa.

✔ Confira: A pasta campus-app tem index.html e style.css.

3Como testar durante a atividade

Nas Partes 1 e 2 (HTML e CSS), abra o index.html com dois cliques e use F5 depois de salvar. Deixe o navegador no modo celular: aperte F12 e depois Ctrl+Shift+M, e escolha um celular, como o iPhone SE ou o Pixel 7.

A parte de PWA (service worker e instalação) não funciona com o arquivo aberto direto do computador (endereço começando com file://). Ela só funciona em HTTPS, por isso vamos testá-la depois de publicar no GitHub Pages.

✔ Confira: O index.html abre no navegador em modo celular (ainda em branco).

1HTML do app

O app tem um topo, quatro telas (Início, Horário, Cardápio e Perfil) e uma barra de abas embaixo, como os apps de celular. Digite cada bloco no final do index.html.

4Esqueleto do app

A meta viewport com viewport-fit=cover deixa o app usar a tela inteira dos celulares com entalhe (notch). O resto é a base de sempre.

📄 index.html · digite no início do arquivo (ele está vazio)
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
  <title>Campus+</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>

12Trocar de tela só com CSS

Este é o truque principal. Todas as telas começam escondidas (display: none). .tela:target mostra a tela cujo id está no endereço: clicou em #horario, aparece a tela Horário.

Mas quando o app abre, o endereço não tem # nenhum. Por isso a terceira regra diz: se o main não tem (:not(:has(...))) nenhuma tela escolhida, mostre a tela Início.

🎨 style.css · digite no final do arquivo
.tela {
  display: none;
  padding: 20px;
  scroll-margin-top: 140px;
}

.tela:target {
  display: block;
}

main:not(:has(.tela:target)) #inicio {
  display: block;
}

.titulo-tela {
  margin-bottom: 16px;
  font-size: 1.4rem;
}

.titulo-secao {
  margin: 24px 0 12px;
  color: var(--cinza);
  font-size: 1rem;
  text-transform: uppercase;
  letter-spacing: 1px;
}
✔ Confira: Só a tela Início aparece. Clique em Horário: a tela troca!

4Manifest: a identidade do app

O manifest.json diz ao celular o nome do app, as cores e onde estão os ícones. Ele é escrito em JSON, um formato de dados com regras rígidas.

19Criar o manifest.json

Crie o arquivo manifest.json e digite o bloco abaixo. O que cada campo faz:
• name: nome completo, aparece na tela de abertura; short_name: nome curto, aparece embaixo do ícone;
• start_url e scope: "./" quer dizer "esta pasta". Use sempre ./ e nunca /: no GitHub Pages o site fica numa subpasta (/campus-app/), e uma barra sozinha apontaria para o lugar errado;
• display: standalone: abre sem a barra do navegador, como um app;
• theme_color: cor da barra de status; background_color: cor da tela de abertura;
• icons: a lista dos ícones da Parte 3.

Cuidado com o JSON: textos entre aspas duplas, vírgula entre os itens e nenhuma vírgula depois do último item de uma lista.

🧾 manifest.json · crie o arquivo e digite (ele está vazio)
{
  "name": "Campus+ · App do Estudante",
  "short_name": "Campus+",
  "description": "Horário, avisos e cardápio do campus no seu celular.",
  "start_url": "./",
  "scope": "./",
  "display": "standalone",
  "orientation": "portrait",
  "background_color": "#f4f6fb",
  "theme_color": "#0B8F4D",
  "lang": "pt-BR",
  "icons": [
    {
      "src": "icon-192.png",
      "sizes": "192x192",
      "type": "image/png"
    },
    {
      "src": "icon-512.png",
      "sizes": "512x512",
      "type": "image/png"
    },
    {
      "src": "icon-maskable-512.png",
      "sizes": "512x512",
      "type": "image/png",
      "purpose": "maskable"
    }
  ]
}
✔ Confira: O arquivo está salvo. No VS Code, nenhuma linha aparece sublinhada em vermelho (se aparecer, é vírgula ou aspas).

20Ligar o manifest no HTML

Agora o HTML precisa avisar que o manifest existe. Atenção: este bloco NÃO vai no final do arquivo. Volte ao index.html e cole logo abaixo da linha <link rel="stylesheet" href="style.css">, dentro do <head>.
• manifest: liga o manifest.json;
• theme-color: pinta a barra do navegador de verde;
• icon: ícone da aba do navegador;
• apple-touch-icon e apple-mobile-web-app-title: o iPhone ainda usa estas tags para o ícone e o nome na tela inicial.

📄 index.html · cole logo ABAIXO da linha <link rel="stylesheet" href="style.css">
  <link rel="manifest" href="manifest.json">
  <meta name="theme-color" content="#0B8F4D">
  <link rel="icon" href="icon-192.png">
  <link rel="apple-touch-icon" href="icon-192.png">
  <meta name="apple-mobile-web-app-title" content="Campus+">
✔ Confira: F5. A aba do navegador mostra o seu ícone.

5Service worker: o app funcionando offline

O service worker é um arquivo JavaScript que o navegador deixa rodando em segundo plano. Ele fica entre o app e a internet: guarda uma cópia dos arquivos e, sem conexão, entrega essa cópia. O Chrome só oferece a instalação se o site tiver um service worker com o evento fetch.

21Lista de arquivos guardados

Crie o arquivo sw.js. VERSAO é o nome da "caixa" (cache) onde os arquivos ficam guardados. ARQUIVOS é a lista do que vai para a caixa. Todos os nomes da lista precisam existir na pasta: se um estiver errado, o service worker inteiro falha.

⚙️ sw.js · crie o arquivo e digite (ele está vazio)
// Nome da caixa (cache). Mude o número quando atualizar o app: v1, v2, v3...
const VERSAO = 'campus-v1';

// Arquivos guardados no celular para o app abrir sem internet
const ARQUIVOS = [
  './',
  './index.html',
  './style.css',
  './app.js',
  './manifest.json',
  './icon-192.png',
  './icon-512.png'
];
✔ Confira: O sw.js tem a versão e a lista com 7 itens.

22Evento install: guardar os arquivos

O evento install acontece uma vez, quando o service worker é instalado. Ele abre a caixa e guarda todos os arquivos da lista (cache.addAll). skipWaiting() faz a versão nova começar a valer logo, sem esperar o app ser fechado.

⚙️ sw.js · digite no final do arquivo
// 1. INSTALAÇÃO: baixa e guarda os arquivos da lista
self.addEventListener('install', (evento) => {
  evento.waitUntil(
    caches.open(VERSAO).then((cache) => cache.addAll(ARQUIVOS))
  );
  self.skipWaiting();
});
✔ Confira: Arquivo salvo.

23Evento activate: jogar fora a versão velha

Quando uma versão nova assume (activate), apagamos as caixas com nomes diferentes da VERSAO atual. Assim o celular não acumula cópias antigas. clients.claim() faz o service worker assumir as telas já abertas.

⚙️ sw.js · digite no final do arquivo
// 2. ATIVAÇÃO: apaga as caixas de versões antigas
self.addEventListener('activate', (evento) => {
  evento.waitUntil(
    caches.keys().then((nomes) =>
      Promise.all(
        nomes.filter((nome) => nome !== VERSAO).map((nome) => caches.delete(nome))
      )
    )
  );
  self.clients.claim();
});
✔ Confira: Arquivo salvo.

24Evento fetch: internet primeiro, cópia se cair

Toda vez que o app pede um arquivo, o evento fetch é chamado. Nossa estratégia é internet primeiro:
• com internet: busca a versão mais nova (fetch), guarda uma cópia na caixa e entrega;
• sem internet: cai no .catch e entrega a cópia guardada (caches.match).
As duas primeiras linhas ignoram pedidos que não são leitura (GET) e pedidos para outros sites.

⚙️ sw.js · digite no final do arquivo
// 3. BUSCA: tenta a internet; se não conseguir, usa a cópia guardada
self.addEventListener('fetch', (evento) => {
  if (evento.request.method !== 'GET') return;
  if (!evento.request.url.startsWith(self.location.origin)) return;

  evento.respondWith(
    fetch(evento.request)
      .then((resposta) => {
        const copia = resposta.clone();
        caches.open(VERSAO).then((cache) => cache.put(evento.request, copia));
        return resposta;
      })
      .catch(() => caches.match(evento.request))
  );
});
✔ Confira: O sw.js está completo, com os três eventos: install, activate e fetch.

// ===== 2. Convite de instalação (Android e computador) =====
let pedidoInstalacao = null;

  evento.preventDefault();

  convite.hidden = false;
});

document.querySelector('#botao-instalar').addEventListener('click', async () => {
  convite.hidden = true;
  if (!pedidoInstalacao) return;
  pedidoInstalacao.prompt();
  const escolha = await pedidoInstalacao.userChoice;
  console.log('Resposta:', escolha.outcome);
  pedidoInstalacao = null;

document.querySelector('#botao-depois').addEventListener('click', () => {
  convite.hidden = true;

window.addEventListener('appinstalled', () => {
  convite.hidden = true;

⚙️ sw.js completo
// Nome da caixa (cache). Mude o número quando atualizar o app: v1, v2, v3...
const VERSAO = 'campus-v1';

// Arquivos guardados no celular para o app abrir sem internet
const ARQUIVOS = [
  './',
  './index.html',
  './style.css',
  './app.js',
  './manifest.json',
  './icon-192.png',
  './icon-512.png'
];

// 1. INSTALAÇÃO: baixa e guarda os arquivos da lista
self.addEventListener('install', (evento) => {
  evento.waitUntil(
    caches.open(VERSAO).then((cache) => cache.addAll(ARQUIVOS))
  );
  self.skipWaiting();
});

// 2. ATIVAÇÃO: apaga as caixas de versões antigas
self.addEventListener('activate', (evento) => {
  evento.waitUntil(
    caches.keys().then((nomes) =>
      Promise.all(
        nomes.filter((nome) => nome !== VERSAO).map((nome) => caches.delete(nome))
      )
    )
  );
  self.clients.claim();
});

// 3. BUSCA: tenta a internet; se não conseguir, usa a cópia guardada
self.addEventListener('fetch', (evento) => {
  if (evento.request.method !== 'GET') return;
  if (!evento.request.url.startsWith(self.location.origin)) return;

  evento.respondWith(
    fetch(evento.request)
      .then((resposta) => {
        const copia = resposta.clone();
        caches.open(VERSAO).then((cache) => cache.put(evento.request, copia));
        return resposta;
      })
      .catch(() => caches.match(evento.request))
  );
});
